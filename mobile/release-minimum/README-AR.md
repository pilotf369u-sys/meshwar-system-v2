# KINTO — الحد الأدنى لصفحات الخصوصية وطلب الحذف

هذا فرع صغير مستقل من main عند5e717436fed47d665ac36690293bf1ad43b4e3f4، منفصل عن حزمة الأتمتة فيPR1109. نقطة الرجوع المعروفة rollback/before-play-integration-20261026 عند نفسالقاعدة. لا يُدمجPR1109 ضمن هذا التعديل.

## التغيير المحدد

- privacy-app-kinto.html: سياسة خاصة بالتطبيق، باسمKINTO وبريد الدعم، دون الاسم الشخصي أو مدة قانونية مفترضة.
- account-deletion.html: طلب حذف عبر البريد، يعمل دون دخول أو تثبيت التطبيق، ويشرح التحقق والبيانات المستثناة والمتابعة.
- إضافة رابطين إلى إعدادات قائمة العميل الحالية. إزالة النص المضاف تعيد ملف القائمة إلى بايتاتmain الأصلية تماماً.
- لاSQL أوEdge أوحذف أوجدول جديد، ولا تغيير فيالفواتير أوالبيع أوالدفع أوالحسابات أوالقارئات أوالتوقيع أوCMS. تبقى صفحةprivacy-kinto.html الحالية دون تعديل.

بعد الموافقة والنشر اليدوي علىهوستنكر فقط، يكون رابط السياسة https://shopkinto.com/privacy-app-kinto.html ورابط طلب الحذف https://shopkinto.com/account-deletion.html. لا توضع الروابط فيConsole قبل فحصهما منشورين دون حساب. لا موافقة دمج أو نشر ضمن إعداد الملفات.

## إجراء المعالجة اليدوية

المسؤول إدارةKINTO عبرsupport@shopkinto.com، وفق اعتماد المالك السابق. أهداف الخدمة رد أولي خلال7أيام ومعالجة خلال30يوماً بعد التحقق؛ نبلغ العميل إن احتاج الطلب وقتاً إضافياً وسببه. ليست هذه مهلة قانونية مفترضة أو حذفاً آلياً.

1. استقبال الرسالة وتسجيل متابعتها في بريد الدعم نفسه، دون سجل عام أو نسخ إضافية لكلمات المرور والمستندات.
2. التحقق من الملكية عبر وسيلة مسجلة أو محادثة الحساب الموثقة. رقم هاتف مكتوب في الرسالة وحده ليس تفويضاً للحذف. لا طلب كلمة المرور أو رمز الدخول أو بيانات البطاقة.
3. المسؤول المخوّل بقاعدة البيانات يراجع الحساب المحدد وارتباطاته وملفاته. لأيحساب له معاملات، تُعد خطة خاصة بالحالة من معاينة للقراءة فقط قبل إجراء أي حذف. لاDELETEعام أو حذف بالاسم/الهاتف، ولا إلغاء طلب أو تصفير رصيد أو تعديل مبلغ بسبب طلب الخصوصية.
4. تحديد أي سجل ضروري يجب الاحتفاظ به لسبب مشروع، والحقول الضرورية ومدته أو معيار انتهائه، وإبلاغ العميل بها. لا تُحتفظ بكل المحادثات والصور لمجرد وجود فاتورة. الحساب ذو رصيد أو نزاع يحتاج معالجة حقوقه دون مصادرة أو إخفاء الرصيد.
5. تنفيذ الخطة المحددة لإزالة بيانات الحساب غير اللازمة والمحتوى والملفات الخاصة. الملفات عبرStorage API أوواجهةStorage، وليس بإزالة صفوفstorage.objects باستخدامSQL. الملفات المشتركة تبقى للآخرين وتزال رابطة العميل فقط. نؤكد زوال الكائن والمرجع المناسب؛ لا نمس ملفات الغير.
6. التنسيق مع مزودي معالجة البيانات عند الحاجة لإزالة نسخ يعالجونها لصالح الخدمة، ومراجعة النسخ اليدوية ذات الصلة وتقييد الاستعادة، وإعادة تطبيق الحذف قبل إعادة أي نسخة إلى الخدمة. لا وعد بانتهاء نسخة غير مفحوصة، ولا حذف احتياط كامل يخص الآخرين دون بديل موثوق.
7. إبطال جلسات الحساب والتحقق من رفض التوكن القديم، وفحص أن سجلات الفواتير الضرورية تبقى صحيحة وأن العميل الآخر وطلباته لم تتغير. تعطيل الحساب وحده لا يكفي.
8. إرسال تأكيد المعالجة يوضح ما حذف وما احتفظ به وسببه ومدته/معياره. يُحفظ أقل قدر لازم من دليل معالجة الطلب، دون إعادة نسخ البيانات المحذوفة إلى ملاحظات عامة.

هذه خطوات تشغيل بشرية، وليست شهادة بأن الحذف الإنتاجي نُفّذ أو مسار آلي مكتمل. قبل تقديم إصدارGoogle: تطبيق الإجراء على حساب اختبار متفق عليه بلا دفع أو طلب حقيقي، وتسجيل النتيجة. لا يُحذف حساب المراجع المحفوظ فيConsole. إن تعذر تنفيذ الحذف فعلياً لحالة الاختبار فلا نغيّر إجابة أمان البيانات لتجاوز المشكلة.

## ما يمكن إغلاقه الآن وما يحتاج المالك

تجهيز النصوص ومسار الطلب والروابط وفحص الشكل والحدود يتم هنا. الدمج والنشر علىهوستنكر يحتاجان طلب المالك، ثم يُفحص الرابطان العامان ونكمل نموذجأمان البيانات. جاهزية هاتين الصفحتين لا تعني جاهزيةAAB أو بدءالاختبار المغلق أو قبولGoogle.

مراجعGoogle التي تحكمهذاالنطاق:
https://support.google.com/googleplay/android-developer/answer/13327111?hl=en
https://support.google.com/googleplay/android-developer/answer/10144311?hl=en

تسمحGoogle ببدءطلبالحذف عبر رابط وبريدخدمةعملاء؛ لا تشترط أتمتة شاملة. وتلزم بالمعالجة الفعلية والتوضيح الصادق للاحتفاظ، وليس نشر صفحة أو تجميد الحساب فقط.
