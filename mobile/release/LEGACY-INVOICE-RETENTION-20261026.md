# حماية هوية الفواتير القديمة — مصدر غير منشور

يضيف المصدر سجلاً خاصاً لحقول هوية الفاتورة السبعة فقط، مرتبطاً بطلب حذف موثق وقرار احتفاظ حالي لسجل الطلب نفسه، بسبب المحاسبة أو اعتماد الفاتورة، وباختيار invoice_identity صراحة. لا نسخ عام لكل العملاء، ولا إعادة كتابة orders أو الفواتير المجمدة أو الأموال أو الحالات. لا تُحفظ كلمات مرور أو رموز جلسات أو أرصدة، ولا بصمة ملف الحساب بما يتضمن بيانات الدخول.

يُستخرج الاسم والكود والهواتف والبلد والمحافظة والعنوان من إسقاط خادمي؛ قارنت8حالات إسقاط SQL الفعلي مع وظائف فاتورة JavaScript الفعلية، بما فيها اللقطة الكاملة/الناقصة وترتيب التعويض والمسافات Unicode. تُرفض البنى غير المفهومة بدلاً من تحويلها تخمينياً. فحص التفاضل محلي ناجح في PostgreSQL مضمّن.

عند غياب ملف العميل فقط، تطلب واجهة الفاتورة السجل المحتفظ به عبر RPC محدد، بتوكن الجلسة في جسم POST وليس URL. إذا رفض مسار الحساب الجلسة فلا محاولة تجاوز عبر السجل. البيانات المحتفظ بها لا تدخل دليل العملاء ولا قوائمهم. القراءة مقيدة بصلاحية الطلب الحالية: العميل لنفسه، الموظف بصلاحية الطلبات، المدير، التاجر المرتبط بالطلب، والفرع/المندوب المعينان. تعتمد هذه التحققات على أدوات الجلسة الحالية؛ لا نبدّل المصادقة. تغير سياق الطلب أو ملكيته يوقف القراءة حتى المراجعة، ولا يعكس التغيير التشغيلي.

نجحت12حالة لواجهة البيانات واختبار طباعة الفاتورة الفعلية في Chromium138: البيانات المحفوظة الكاملة أولاً؛ ولفواتير قديمة بملف مفقود، قراءة واحدة مقيدة بالجلسة للهوية المحتفظ بها. لا حساب/دفع حقيقي ولا اتصال إنتاج.

أضيف فحص PostgreSQL17 للمصدر الكامل: منع الحفظ دون قرار احتفاظ، هوية المالك، تكرار الحفظ، سرية الجدول، قراءة المدير والفرع والتاجر والمندوب في نطاقهم، رفض الدور/الجلسة/الطلب الآخر، حذف ملف العميل المصطنع فعلياً مع بقاء الفاتورة والطلبات والعميل الآخر، ورفض السياق المتغير. دوال هوية بعض الأدوار داخل هذه الحزمة الاختبارية بدائل صريحة؛ اختبارها لا يعد تأهيلاً جديداً لمصادقة الإنتاج. يستخدم اختبار النطاق دالة رؤية الطلب الموجودة نفسها من المصدر. نتيجة هذا الفحص الشامل تنتظر CI، فلا تُسجّل ناجحة قبل ذلك.

ملف الرجوع يعطل نقطتي الحفظ والقراءة ويحتفظ بالسجل الخاص؛ لا يحذف السجل الضروري ولا يدعي إعادة ملف عميل محذوف. لا زر حذف حساب جديد، ولا تفعيل للحذف المتكامل ولا SQL إنتاجي أو دمج/نشر. يحتاج المنهي المستقبلي إلى تأهيل الاحتفاظ بهذه السجلات مع بقية العلاقات، ومراجعة النسخ، قبل وصف الحساب بأنه حُذف بالكامل.
