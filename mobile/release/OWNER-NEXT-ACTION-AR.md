# الخطوة الحالية من المالك — تعريف قارئ الفاتورة للقراءة فقط

تم إرسال تذكرة دعم التخزين بنجاح حسب صورة تأكيد المالك. لا تعِد إرسالها؛ ننتظر الرد الخاص بسلوك الرفع الجاري.

يمكننا بالتوازي حسم اعتماد الفواتير القديمة على ملف العميل. التقرير السابق يحتوي بصمة دالة الفاتورة، لكنها لا تطابق نصوص V94/V95/V96 الموجودة في المستودع. قد يكون السبب تنسيقاً فقط؛ لا نستنتج وجود خلل أو نغيّر الدالة بناءً على البصمة.

المطلوب الآن:

1. افتح **SQL Editor** في مشروع KINTO كما فعلت سابقاً.
2. نفّذ محتوى `sql/kinto-privacy-invoice-contract-readonly-v1.sql` فقط.
3. أعد لنا نتيجة `invoice_contract_report` كاملة.

الاستعلام داخل معاملة READ ONLY، ويقرأ تعريف دالتين محددتين من كتالوج PostgreSQL فقط: قارئ تفاصيل فاتورة التاجر، ومساعد تحليل JSON المرتبط به. لا يستدعي قارئ الفاتورة، ولا يقرأ سجلات عملاء أو طلبات، ولا يغيّر دالة أو سياسة. يوضح الغياب أو تجاوز حد حجم التعريف صراحة دون إرجاع نص مبتور.

هذه ليست ملفات تثبيت الخصوصية أو تفعيل حذف الحساب. لا تحتاج دمجاً أو تحديث هوستنكر أو التطبيق لهذه الخطوة. بعد وصول التعريف نطابق السلوك الفعلي، ونكمل معالجة بيانات الحساب دون افتراض أن لقطة فاتورة غير فارغة مكتملة.
