# التقييمات والصور — تغيير مستقل مطلوب قبل إغلاق الجاهزية

## الموجود والفجوة

الموجود: تقييم عميل مرتبط بمنتج/طلب، صور، نشر/رفض من الأدمن وأسباب رفض. فحص customer-product-reviews-v135.js وstore-product-reviews-v140.js وadmin-product-reviews-v138.js والبحث فيjs/sql لم يثبت واجهة إبلاغ عن التقييم وصاحبه، أو حظر صاحبه، أو قبول سياسة محتوى قبل إنشاء/رفع المحتوى. عدم العثور ليس تدقيقاً كاملاً لكل إعداد إنتاج؛ يلزم إثبات وجود البديل إن كان منفذاً بمسار آخر.

## نطاق مقترح قابل للمراجعة

1. قواعد تقييم واضحة قبل أول نشر/رفع: محتوى متعلق بالمنتج، منع الإساءة والتهديد والمحتوى غير القانوني والمحتوى الجنسي والبيانات الشخصية والدعاية المزعجة وانتهاك الحقوق. قبول صريح محفوظ بإصدار القواعد؛ لا علامة قبول تلقائية.
2. قائمة على كل تقييم منشور: إبلاغ عن المحتوى، إبلاغ عن صاحبه، حظر تقييمات هذا المستخدم. لا نكشف معرف العميل الداخلي أو هاتفه للناس. التقييم وصاحبه يحددهما الخادم من معرف التقييم، لا بيانات ثقة من المتصفح.
3. تذكرة إبلاغ محمية جلسياً إلى طابور الأدمن، مع سبب محدد، معدل طلبات محدود، ومنع التكرار والتلاعب. البلاغ ليس حذفاً أو رفضاً تلقائياً، ولا يغيّر النقاط أو السعر أو المخزون.
4. الحظر يخص مشاهدة المحتوى والتفاعل المناسب؛ لا يلغي طلباً أو يوصل إلى بيانات صاحب التقييم. يحدده نوع التفاعل الموجود. لا نفترض أن حظر المشتري لدى التاجر أو تعطيل حسابه هو الأداة المقصودة. محادثة العميل مع فريق الدعم تفحص بحسب طبيعتها؛ لا نزيل دعم الطلب النشط بقرار عرضي.
5. الأدمن يستعرض البلاغ ويعالج المحتوى/الإساءة عبر أدواته، بسجل تدقيق وإشعار مناسب. التقييمات السلبية السليمة لا تحذف بسبب عدم رضا التاجر عنها.
6. اختبارات عزل: لا قراءة بلاغات الآخرين، لا حظر حساب آخر نيابة عن المستخدم، لا كشف هوية خاصة، حد التكرار، بقاء مراجعة الأدمن والتقييم والطلب والفاتورة كما هي.
